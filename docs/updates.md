# Версии и обновление

## Для владельца роутера

**LuCI → Службы → VPN-маршрутизация → Состояние → «Версия и обновления».**

- Роутер раз в сутки (ночью, в случайную минуту) сам проверяет, есть ли новая версия. Проверить сразу — кнопка **«Проверить обновления»**.
- Если версия новее, показывается список изменений и кнопка **«Обновить до X.Y.Z»**. Установка занимает около минуты, интернет пропадает на несколько секунд, страница перезагружается сама.
- Настройки (`/etc/config/vpnroute`) при обновлении не меняются.

Из командной строки:

```
vpnroute version          установленная версия
vpnroute update check     проверить
vpnroute update install   установить (в фоне)
vpnroute update status    ход установки и журнал (JSON)
```

## Как устроено

```
GitHub                                   роутер
main: files/usr/share/vpnroute/VERSION ◄── update check (cron раз в сутки, кнопка)
тег vX.Y.Z: CHANGELOG.md               ◄── список изменений новее установленной
тег vX.Y.Z: архив кода                 ◄── update install → scripts/install.sh
```

- Номер последней версии берётся из файла `VERSION` в ветке `main` через `raw.githubusercontent.com`. API GitHub не используется: у него лимит запросов на внешний IP, а за CGNAT этот IP делят многие абоненты.
- Код скачивается строго по тегу `vX.Y.Z`, поэтому незаконченные правки из `main` на роутер не попадают. Если версия в `main` есть, а тега нет, проверка сообщит, что релиз не найден.
- Установка идёт в фоне (`start-stop-daemon`), потому что установщик перезапускает `rpcd`, через который работает LuCI. Пакеты доустанавливаются, только если в новой версии появились новые зависимости.
- Файлы: `/usr/share/vpnroute/update.uc`, состояние и журнал в `/tmp/vpnroute-update/`, строка в `/etc/crontabs/root`.
- Репозиторий можно сменить (например, на форк): `uci set vpnroute.main.update_repo='владелец/репозиторий'`.

## Выпуск версии

1. Поднять версию в [files/usr/share/vpnroute/VERSION](../files/usr/share/vpnroute/VERSION): исправления — `PATCH`, новые возможности — `MINOR`, несовместимые изменения настроек — `MAJOR`.
2. Добавить в [CHANGELOG.md](../CHANGELOG.md) раздел `## X.Y.Z — дата`. Его увидит владелец роутера перед обновлением, поэтому пишите понятным языком.
3. Закоммитить.
4. Запустить `.\scripts\release.ps1`. Скрипт проверит, что всё закоммичено, раздел в CHANGELOG есть, а тега ещё нет, создаст тег `vX.Y.Z` и отправит `main` вместе с тегом на GitHub одной операцией.

Ручная установка через `deploy.ps1` по-прежнему работает и ставит текущее состояние рабочей папки.
