# Диагностика трафика устройства

Помогает найти, что не работает напрямую из-за ограничений провайдера, и сразу отправить это в VPN.

**LuCI → Службы → VPN-маршрутизация → Диагностика.**

## Как пользоваться

1. Выберите устройство и длительность записи (5–60 минут), нажмите **«Начать запись»**.
2. На устройстве откройте сайт или приложение, которое не работает.
3. Таблица обновляется каждые 2 секунды. Поставьте фильтр **«Статус: Только проблемы»**.
4. Нажмите **«+»** в строке. В окне выберите, что добавить (домен целиком или поддомен, IP или подсеть /24) и в какой список, или создайте новый список.
5. Перезапустите браузер или приложение на устройстве: оно может помнить старый адрес.

Запись останавливается сама по таймеру или кнопкой **«Остановить»**. Хранится последний сеанс, до перезагрузки роутера.

## Статусы

Статус — это вероятная причина по поведению соединения, а не точный диагноз.

| Статус | Как распознаётся | Что обычно значит |
|---|---|---|
| ✅ Работает | Данные идут в обе стороны | Всё в порядке |
| ⏳ Устанавливается | Соединению меньше 3 секунд | Статус ещё не ясен |
| ⛔ Нет ответа | TCP: ответа на запрос соединения нет. UDP: ни одного ответного пакета | Блокировка по IP или сервер недоступен |
| ⛔ Сброс соединения | TCP закрылось сбросом в первые 15 секунд, пришло меньше 2 КБ | Блокировка по имени сайта (DPI) |
| ⚠️ Зависание ~16 КБ | TCP на порт 443: пришло 12–24 КБ, и 15 секунд данных нет | Замедление оборудованием провайдера (ТСПУ) |
| ⚠️ QUIC без ответа | UDP на порт 443 без ответа | Блокировка QUIC. Браузер обычно переходит на TCP, это не всегда проблема |
| ⛔ DNS: домен не найден / ошибка сервера / отказ / нет ответа | Ответ DNS провайдера | Блокировка на уровне DNS или сбой DNS провайдера |
| 🚫 Заблокировано роутером | dnsmasq ответил по своим настройкам | DoH-серверы, которые vpnroute блокирует намеренно |
| · Закрыто (VPN) | Соединение через VPN закрылось сбросом | Закрыл Xray или само приложение. Обычно не проблема |
| · Локальная сеть | Адрес назначения в локальной сети | Скрывается фильтром по умолчанию |

Соединения через VPN на устройстве держит сам Xray на роутере, поэтому для них «Сброс» показывается как «Закрыто (VPN)», а «Зависание» не определяется.

**Домен неизвестен** обычно у соединений с адресами, которые устройство узнало до начала записи. Начните запись, затем перезапустите браузер или приложение. Взять домены из кеша dnsmasq не получится: при старте записи dnsmasq перезапускается и кеш очищается, а служебные адреса VPN выдаются со временем жизни 1 секунда.

Возможны ложные срабатывания: рекламные и аналитические домены, долгие простаивающие соединения, проба QUIC перед TCP. Группировка по домену помогает отделить сайт, у которого не работает всё, от единичных сбоев.

## Фильтры

- **Статус**: все, только проблемы, отдельный статус, ошибки DNS.
- **Путь**: напрямую или VPN.
- **Протокол**: TCP, UDP, DNS.
- **Поиск** по домену или IP.
- **Группировать по домену**: все соединения к одному домену в одной строке, со счётчиками статусов.
- **Скрыть локальный трафик** (включено по умолчанию).

Показывается не больше 400 строк. Если записей больше, уточните фильтры.

## Как устроено

```
LuCI ──vpnroute trace start <IP> <мин>──► служба vpnroute-trace (procd)
                                            └─ ucode trace.uc run <IP> <сек>
                                                 ├─ раз в секунду /proc/net/nf_conntrack
                                                 ├─ журнал DNS dnsmasq (только на время сеанса)
                                                 └─ каждые 2 с → /tmp/vpnroute-trace/state.json
LuCI ◄──vpnroute trace dump── state.json + «идёт ли запись»
```

- **Соединения** берутся из таблицы ядра с учётом байт и пакетов в обе стороны. Закрытые соединения остаются в таблице от 10 секунд до 2 минут, поэтому опроса раз в секунду хватает без дополнительных пакетов.
- **Домены.** На время сеанса dnsmasq пишет расширенный журнал запросов (`log-queries=extra`) в `/var/run/dnsmasq/vpnroute-trace.log`. Номер запроса связывает запрос с ответом, ответные адреса связывают соединения с доменами. В записи остаются только A-запросы устройства.
- **Путь VPN**: адрес из диапазона FakeDNS `198.18.0.0/15`, адрес из списков IP или устройство в режиме «весь трафик через VPN».
- **Включение журнала DNS** — файл `vpnroute-trace.conf` в каталоге настроек dnsmasq (`/tmp/dnsmasq.<секция>.d/`) и перезапуск dnsmasq. При остановке файл удаляется, dnsmasq перезапускается снова. DNS пропадает примерно на секунду в начале и в конце. После перезагрузки роутера журнал выключен в любом случае: каталог лежит в `/tmp`.
- **Ограничения памяти**: до 1500 соединений и 800 DNS-запросов за сеанс, старые вытесняются.
- **Автоостановка**: по истечении времени сборщик сохраняет итог, выключает журнал DNS (`vpnroute trace stop --from-collector`) и завершается.

## Командная строка

```
vpnroute trace devices                 устройства локальной сети
vpnroute trace start 192.168.2.107 15  запись на 15 минут
vpnroute trace status
vpnroute trace dump                    данные в JSON
vpnroute trace stop
vpnroute list-add <секция списка> instagram.com
vpnroute list-add new cdninstagram.com "Instagram"
```

## Что проверено

2026-10-24, на временном виртуальном клиенте: домены и путь (напрямую / VPN) для соединений и DNS, статусы «Работает», «Нет ответа» (TCP), «DNS: домен не найден», «DNS: ошибка сервера», «Заблокировано роутером», ручная и автоматическая остановка. Не проверены на живом трафике: «Сброс соединения», «Зависание ~16 КБ», «QUIC без ответа» и UDP без ответа (в прошивке `nc` без UDP), страница в браузере.
