# Как устроен vpnroute

## Общая схема

```
                       ┌──────────────── роутер ────────────────────────────┐
 устройство ──DNS──►   │ dnsmasq ──(домен из списка)──► Xray DNS (FakeDNS)  │
                       │    │                         отвечает 198.18.x.x   │
                       │    └──(остальные)──► DNS провайдера                │
                       │                                                    │
 устройство ──трафик─► │ nftables (prerouting):                             │
                       │   локальные сети ............... напрямую          │
                       │   198.18.0.0/15 (FakeDNS) ─┐                       │
                       │   IP из списков ───────────┼─► TPROXY ─► Xray ─► VPN-сервер
                       │   MAC из «всё в VPN» ──────┘                       │
                       │   остальное ................... напрямую (NAT)     │
                       └────────────────────────────────────────────────────┘
```

## Домены: FakeDNS

1. Устройство спрашивает у роутера адрес `youtube.com`.
2. В файле `/etc/vpnroute/dnsmasq.servers` есть строка `server=/youtube.com/127.0.0.1#1053`, поэтому dnsmasq передаёт запрос не провайдеру, а в Xray. Строка действует и на все поддомены.
3. Xray отвечает **служебным адресом** из диапазона `198.18.0.0/15` и запоминает, какому домену он выдан.
4. Устройство подключается к этому адресу. Правило nftables отправляет весь трафик на `198.18.0.0/15` в Xray (TPROXY).
5. Xray по адресу восстанавливает домен и отправляет соединение в туннель **с именем домена**. Настоящий адрес узнаёт VPN-сервер.

Что это даёт:
- DNS провайдера для доменов из списков не используется вообще, его подмена и вырезание записей не мешают;
- не бывает гонки, когда соединение успело уйти напрямую раньше, чем адрес попал в список;
- общие адреса CDN не тянут в туннель посторонние сайты.

Ограничения:
- Работает только для устройств, которые спрашивают DNS у роутера. Поэтому включены перехват DNS, блокировка DoT (порт 853) и известных DoH-серверов.
- После перезапуска Xray соответствие «адрес → домен» теряется. Если устройство закешировало старый служебный адрес, такое соединение отбрасывается, и браузер повторяет запрос DNS. Xray перезапускается только при изменении серверов или общих настроек; правка списков и устройств его не перезапускает.
- Кириллические домены нужно вводить в punycode (`xn--…`).

## IP-адреса и подсети

Хранятся в наборе nftables `inet vpnroute dst4`. Трафик к ним уходит в Xray через TPROXY и дальше в туннель по IP.

## Устройства «весь трафик через VPN»

- MAC-адрес устройства попадает в набор `inet vpnroute tunnel_macs`.
- Весь его TCP/UDP-трафик, кроме локальных сетей, уходит в Xray.
- Его DNS-запросы перенаправляются сразу в Xray, минуя dnsmasq: все домены получают служебные адреса и резолвятся VPN-сервером. Утечки DNS к провайдеру нет.
- Переключение меняет только набор nftables, Xray не перезапускается. Уже открытые соединения устройства оборвутся и переподключатся по новому пути.

## Падение туннеля

Xray раз в минуту проверяет серверы (`probe_url`). Если не отвечает ни один и включено «Напрямую при недоступности VPN», трафик из списков идёт напрямую через Xray. DNS при этом берётся у `dns_upstream` (по умолчанию DoH Cloudflare), а не у провайдера.

## Компоненты

| Файл | Назначение |
|---|---|
| `/etc/config/vpnroute` | Все настройки (UCI). Их редактирует LuCI |
| `/usr/share/vpnroute/gen.uc` | Из настроек собирает три файла: конфигурацию Xray, правила nftables, файл для dnsmasq |
| `/etc/init.d/vpnroute` | Служба: запускает генератор, проверяет конфигурацию Xray, применяет правила, запускает Xray через procd |
| `/usr/bin/vpnroute` | Командная утилита |
| `/etc/hotplug.d/iface/90-vpnroute` | Восстанавливает правило маршрутизации после перезапуска сети |
| LuCI: `view/vpnroute/*.js` | Страницы «Состояние» и «Настройки» |

Сгенерированные файлы:
- `/var/etc/vpnroute/xray.json` — конфигурация Xray;
- `/var/etc/vpnroute/vpnroute.nft` — таблица `inet vpnroute`;
- `/etc/vpnroute/dnsmasq.servers` — подключён к dnsmasq через `dhcp.@dnsmasq[0].serversfile`; dnsmasq перечитывает его по сигналу HUP без перезапуска.

## Что происходит при «Сохранить и применить»

1. LuCI сохраняет `/etc/config/vpnroute`, procd вызывает `vpnroute reload`.
2. Генератор пересобирает файлы и сообщает, какие изменились.
3. Таблица nftables заменяется целиком одной операцией.
4. Если изменился файл для dnsmasq — dnsmasq получает HUP (перечитывает список, очищает кеш).
5. Если изменилась конфигурация Xray — procd перезапускает Xray, иначе он продолжает работать.

## Используемые ресурсы роутера

- Метка пакетов `0x40000`, таблица маршрутизации `107`, правило с приоритетом `1107`.
- Порты на роутере: `12701` (TPROXY), `1053` (DNS Xray). Из интернета закрыты межсетевым экраном.
- Таблица nftables `inet vpnroute`, независимая от `inet fw4`.
