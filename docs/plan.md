# План и состояние работ

Последнее обновление: 2026-10-24.

## Текущее состояние

vpnroute установлен на Xiaomi AX3000T и работает в штатном режиме:

| | |
|---|---|
| Роутер | Xiaomi AX3000T, стандартная разметка памяти (`xiaomi,mi-router-ax3000t`) |
| Прошивка | OpenWrt 25.12.6, менеджер пакетов apk |
| Подключение | WAN напрямую к провайдеру (CGNAT, адрес 100.x), локальная сеть 192.168.2.0/24, роутер 192.168.2.1 |
| Xray | 26.3.27 (пакет `xray-core`) |
| Сервер | один, VLESS/TCP/TLS |
| Проверено владельцем | туннелирование по списку доменов (YouTube), «весь трафик устройства через VPN» |

### Найдено и исправлено при установке

- `devices` — зарезервированное слово nftables. Набор MAC-адресов переименован в `tunnel_macs`.
- `redirect to :порт` требует явного `udp`/`tcp` в том же правиле. Правило перенаправления DNS разделено на два.
- dnsmasq в OpenWrt работает в изоляции (ujail) и монтирует сам файл `/etc/vpnroute/dnsmasq.servers`. Если файл заменить новым, dnsmasq продолжает читать старый, удалённый. Генератор теперь перезаписывает этот файл на месте.

### Как проверять трафик

На ПК владельца работает свой VPN-клиент (интерфейс `singbox_tun` с маршрутом по умолчанию), поэтому проверка с ПК не показательна. Для проверки с роутера можно временно создать виртуального клиента локальной сети:

```sh
apk add kmod-veth
ip link add vrtest0 type veth peer name vrtest1
ip netns add vrtest
ip link set vrtest1 netns vrtest
ip link set vrtest0 master br-lan up
ip netns exec vrtest ip link set lo up
ip netns exec vrtest ip link set vrtest1 up
ip netns exec vrtest ip addr add 192.168.2.250/24 dev vrtest1
ip netns exec vrtest ip route add default via 192.168.2.1
ip netns exec vrtest nslookup example.com 192.168.2.1     # ждём 198.18.x.x или 198.19.x.x
# ... запросы с клиента: ip netns exec vrtest uclient-fetch ...
logread | grep xray                                       # видно, куда ушло соединение

# убрать за собой
ip netns del vrtest; ip link del vrtest0; apk del kmod-veth
```

Для подробного журнала временно поставьте `log_level` = `info` (LuCI → Настройки → Общие).

## Риски

| Риск | Что делаем |
|---|---|
| Устройство кеширует старые служебные адреса после перезапуска Xray | Xray перезапускается только при смене серверов и общих настроек. Если сайт не открывается — перезапустить браузер или переподключить Wi-Fi |
| Приложения с собственным DoH на нестандартных адресах | Добавлять адреса этих DoH-серверов в блокировку по мере обнаружения |
| Обновление пакета `xray-core` переименует поля конфигурации | Служба проверяет конфигурацию перед запуском (`xray run -test`) и пишет ошибку в журнал. Поправить генератор |
